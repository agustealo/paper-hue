# Real screenshot capture plan

Paper Hue documentation screenshots must be captured from a real running WordPress installation with the theme activated and configured. Mockups and generated substitutes do not count as product proof.

## Required captures

1. Front page desktop with Hero Slider, Featured Story, and Recent Articles.
2. Front page mobile.
3. Hero Slider with controls visible.
4. Featured Story section.
5. Recent Articles section.
6. Single post.
7. Archive/category page.
8. WordPress Customizer opened to Paper Hue settings.
9. Appearance → Paper Hue control center.
10. Site Identity/logo state.
11. Footer state.
12. Static front-page variant.

## Capture requirements

- Current WordPress runtime supported by the release.
- Real Paper Hue theme files from the exact candidate commit.
- Real WordPress posts, categories, images, menus, widgets, and theme mods.
- Desktop and mobile viewport evidence.
- No screenshots from design tools or generated UI imagery.
- Keep a capture ledger recording candidate SHA, WordPress/PHP versions, viewport, route, and relevant configuration state.

Capture begins after the homepage feature slice stabilizes so documentation is not immediately stale.
